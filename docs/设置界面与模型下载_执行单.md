## 1. 问题定义

### 1.1 「GPU 不可用」是误报（已实测）

```
verify_cuda(D:\Code\SideProject\Vidnote\models\large-v3)
→ ok=True / 真实推理通过（输入 1.0s，device=cuda） / 9.7s
```

根因链：

| # | 位置 | 行为 |
|---|---|---|
| 1 | `%LOCALAPPDATA%\Vidigest\config.yaml` | `model_dir` → `C:\...\Local\Vidigest\models`，**该目录不存在** |
| 2 | `app/core/env_probe.py:310-312` | `if not model_dir.exists(): return False, "模型不存在…"` ⇒ **`False` 被读成「GPU 不可用」** |
| 3 | `app-ui/src/components/StatusBar.tsx` `gpuView()` | `!w.gpu_usable` → 红字「GPU 不可用」+ title「吞吐下降约 6 倍」（**错的**） |

**本质**：`verify_cuda` 返回 `tuple[bool, str]`，把「模型没装（没验成）」和「CUDA 不可用（验了，不行）」混成同一个 `False`。三态布尔的设计意图（`PLAN §9.1`）在这一层被塌成二态。

**附带**：`detail` Python 侧**已经发了**（`app/rpc.py:359-366`），Rust **没存进快照**（`app-ui/src-tauri/src/worker/mod.rs:686-695` 只取 `gpu_usable` / `concurrency`）⇒ UI 永远拿不到真原因。

### 1.2 首启不可用违背 D1

PRD **D1 = 装完即用，不需要终端/命令行**。现状：装完第一眼是红字，唯一出路是照 README 第 3 步手敲 5 条 `curl`。目标用户做不到。

镜像已实测可达（2026-10-24，HTTP 200 全通过）：

| 文件 | 大小 |
|---|---|
| `model.bin` | **2944.3 MiB** |
| `tokenizer.json` | 2.4 MiB |
| `vocabulary.json` | 1.0 MiB |
| `config.json` / `preprocessor_config.json` | < 0.1 MiB |
| **合计** | **≈ 2.88 GiB** |

## 2. 设计决策（先定，避免后面返工）

| # | 决策 | 理由 | 代价 |
|---|---|---|---|
| **D-S1** | 设置改动**一律「写盘 + 重启 worker」生效**，不做热应用 | 热应用要重建 `Dispatcher`、重算并发、清 `_MODEL_CACHE`、重建线程池 —— 每条都是新 bug 面。重启只 2–3 s，且 `worker_restart` 与自动重启机制已存在 | 改配置会中断正在跑的任务 ⇒ **有任务在跑时设置页只读**（见 §4.3） |
| **D-S2** | 模型下载走**独立线程 + 事件推送**，不进 `Dispatcher` | 它不属于任务流水线，不该被 `pause` / `cancel_task` 影响；且必须在 `start` 之前就能用 | 多一个线程与一套生命周期（取消 / 超时 / 异常） |
| **D-S3** | 下载校验 = **大小比对 + 一次真实加载**（复用 `verify_cuda`） | 无权威 sha256 来源；「模型能加载并跑出结果」是比哈希更强的判据 | 校验阶段约 10 s，需在 UI 上显示为「校验中」而不是卡住 |
| **D-S4** | 误报修复用**结构化 `blocked_reason`**，不靠字符串前缀判断 | 裸字符串一旦改文案就断；reason code 可被 UI / 测试同时消费 | 协议要加字段（兼容：新增可选字段，`v` 仍为 1） |
| **D-S5** | `beam_size` / `vad_min_silence_ms` **默认只读**，改动需二次确认并显式告知「会让阶段 1 的 662 段基线失效」 | 这两个参数直接决定分段边界（`app/models/config.py:104-107` 已写明） | 一个受控例外分支 |

## 3. 后端实现

### 3.1 修误报（P0，可独立交付）

**`app/core/env_probe.py:292`** —— `verify_cuda` 返回改为 `tuple[bool | None, str, str]`：

| 情形 | `ok` | `reason` | 行号 |
|---|---|---|---|
| 模型目录不存在 | `None` | `"model_missing"` | :310-312 |
| 模型目录在但缺 `model.bin` | `None` | `"model_incomplete"` | 新增（检查 5 个必需文件） |
| CUDA 运行库加载失败 | `False` | `"cuda_load_failed"` | :341-344 |
| 能加载但推理失败 | `False` | `"cuda_inference_failed"` | :346-352 |
| 通过 | `True` | `""` | :355 |

⚠️ **`ok=None` 必须同时意味着「并发不回退到 CPU」** —— `app/rpc.py:352-353` 现有逻辑已是如此（`ok is None` ⇒ 用 `quick_gpu_usable`），**不要改**。

**`app/rpc.py:341`** `_apply_env_verification(self, ok, detail)` → 增加 `reason: str = ""`；:359-366 的事件 payload 加 `"blocked_reason": reason or None`。

**关键语义**（写进协议规格）：
> `gpu_usable` 为 `false` **只表示「验过，确实不能用」**。`gpu_usable` 为 `null` 且 `blocked_reason` 非空表示「因环境缺失没能验」，两者不可互换。

### 3.2 新增 RPC 命令（4 条）

加在 `app/rpc.py:189-213` 的 `_handlers` 表：

| 命令 | args | 响应事件 | 说明 |
|---|---|---|---|
| `get_config` | `{}` | `config` | 返回全量配置 + 元信息（`path` / `is_default` / `model_path` / `model_present` / `model_size_bytes` / `read_only_fields`） |
| `set_config` | `{"patch": {...}}` | `config_saved` | **部分更新**（深合并到对应 section），先 `validate()` 再 `save()`；成功后才允许 Rust 重启 worker |
| `download_model` | `{"model": "large-v3"}` | `model_download_progress` → `model_download_done` \| `model_download_failed` | 幂等：已齐全则立刻 `done` |
| `cancel_model_download` | `{}` | `model_download_cancelled` | 置取消标志，下载线程在下一个 chunk 边界退出并删 `.part` |

**`set_config` 的安全边界**（写进实现，不是文档装饰）：
- 只接受白名单 section（`paths` / `runtime` / `transcribe` / `frames` / `summarize` / `download`），未知键丢弃并回 `warnings`
- `paths.*` 若是相对路径，按 `app_root()` 解析后**存绝对路径**（避免日后 cwd 变化导致漂移）
- `summarize.api_key` **永不允许**写入（密钥只走环境变量，`config.py:130-137` 的设计）
- `beam_size` / `vad_min_silence_ms` 若与当前值不同，`config_saved.warnings` 里必须带一条 `E_BASELINE_PARAM_CHANGED`

### 3.3 新增 `app/core/model_downloader.py`

```
MODEL_FILES = ["config.json", "preprocessor_config.json", "tokenizer.json",
               "vocabulary.json", "model.bin"]
BASE_URL = "https://hf-mirror.com/Systran/faster-whisper-{model}/resolve/main/"
```

- 每文件下到 `<file>.part`，`Range` 续传；完成后 `os.replace` 原子改名
- 进度事件节流：**≥ 200 ms 或 ≥ 1% 才发一次**（否则 `model.bin` 2.9 GiB 会把 stdout 打爆）
- payload：`{"file", "file_index", "file_count", "done_bytes", "total_bytes", "overall_pct", "bytes_per_sec", "eta_sec"}`
- 全部完成 → `verify_cuda()` 一次（D-S3）→ `model_download_done {verified, detail, blocked_reason}`
- 失败重试 3 次、指数退避；`URLError` / `HTTPError` 分类写进 `detail`
- **不新增第三方依赖**（`urllib.request` 足够；`requests` 虽在依赖里但没必要）

### 3.4 生效路径

```
前端保存 → Rust worker_send("set_config") → Python 写盘 + 回 config_saved
        → Rust 收到 config_saved → 调用 worker.restart()
        → 新 worker 走 hello → ready（带新的 concurrency / gpu_usable）
```

**Rust 侧要新增的分支**：`mod.rs` 的事件处理 match 里加 `"config_saved"` → `self.restart()`。
⚠️ 必须**只在这个事件上重启**，不能在 `worker_send` 里无脑重启。

### 9.2 与执行单的 4 处偏差（都记录在案）

1. **命令是 5 条不是 4 条**：补了 `verify_env`。设置页的「重新校验」和「改完
   `model_dir` 立刻看结论」都需要它，否则用户只能重启应用才能触发一次验证。

   是「转发给前端之后再延 80 ms 重启」，而不是在 `handle_frame` 里同步重启 ——
   否则 `config_saved`（含 `warnings`）可能还没到前端，界面就只看到转圈。
3. **新增 `Inner::child_gen` 代号守卫**（执行单未预见）。原来的 `on_worker_exit`
   会在旧一代读线程 EOF 时 `child.lock().wait()` —— 而重启已经把 `child` 换成新一代，
   于是 `wait()` 会阻塞到新 worker 退出，同时把 `alive` 置 false 并触发一次多余重启。
   这个坑原本只在「worker 已死时手动重启」下不可达，**「保存即重启」让它成了正常路径**。
4. **`DownloadConfig` 新增 `base_url` 字段**（执行单 §6 R1 提过，这里落实成配置项）：
   镜像失效时不用改代码。默认 `None` = 用 `model_downloader.DEFAULT_BASE_URL`。

### 9.4 一个会让人误判的启动顺序（不是 bug，但要知道）

启动时 `hello` 先回 `gpu_usable=quick_gpu_usable`（= `bool(cuda.device_count)`，
`app/rpc.py:500`），**它不看模型在不在**；随后 `env-verify` 后台线程（`app/rpc.py:269`）
才推真正的三态结论。所以「模型缺失」的机器上，界面会**先显示「GPU 可用 · 未验证」约 1–3 s，
再翻成「模型未安装」** —— 先快后准，不是闪回。若日后要消掉这段窗口，得让 `hello`
也带上 `missing_model_files()` 的结果，代价是每次握手多一次磁盘 stat。
