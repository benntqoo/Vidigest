## 0. 结论

| 问的问题 | 结论 |
|---|---|
| 安装配置是否符合标准？ | ✅ **是**。全部元素都能对应到 **Tauri 2 官方 WiX 模板**，未发现本项目自定义增删的安装动作 |
| 卸载能否卸干净？ | ✅ **程序侧能**（程序文件 / 快捷方式 / 自己的注册表值都会清）。⚠️ **但故意不删用户数据目录** —— 见 §4 |
| 有没有侵入系统？ | ❌ **没有**。无服务、无驱动、无计划任务、无开机自启、无防火墙规则、无 hosts / PATH 修改、**不写 HKLM** |
| 有没有注入系统？ | ❌ **没有**。代码零注入类 API；Rust 依赖仅 Job Object 级别（§5） |

**三条必须知情的项**（都不是"违规"，但不该在装的时候被意外发现）：

1. **MSI 与 exe 均未数字签名** ⇒ UAC 会显示「未知发布者」，SmartScreen 可能拦一次。见 §2.4。
2. 包内含 **Tauri 的 WebView2 引导动作**：**仅当机器未安装 WebView2 时**，安装过程会用 PowerShell 联网下载并静默安装它。**本机已装 WebView2（`pv=149.0.4022.80`）⇒ 本次不会触发**。见 §2.3。
3. `InstallScope="perMachine"` ⇒ **需要管理员权限**，装到 `C:\Program Files\Vidigest`。见 §2.1。

### 2.3 ⚠️ WebView2 引导动作（要知情的第一件事）

```
powershell.exe -NoProfile -windowstyle hidden
  try { [Net.ServicePointManager]::SecurityProtocol = [Net.SecurityProtocolType]::Tls12 } catch {};
  Invoke-WebRequest -Uri "https://go.microsoft.com/fwlink/p/?LinkId=2124703"
      -OutFile "$env:TEMP\MicrosoftEdgeWebview2Setup.exe";
  Start-Process -FilePath "$env:TEMP\MicrosoftEdgeWebview2Setup.exe"
      -ArgumentList ('/silent','/install') -Wait
```

- **性质**：这是 **Tauri 官方 WiX 模板的固定内容**（不是本项目写的），用于保证依赖的 WebView2 运行时存在。
- **触发条件**：仅当三个位置的注册表**都没有** WebView2 版本号时才执行（HKLM 两处 + HKCU 一处，`main.wxs:2267-2271`）。
- **本机实测**：`HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F3017226-...}` **存在，`pv=149.0.4022.80`** ⇒ **`INSTALLED_WEBVIEW2_VERSION` 有值 ⇒ 本次安装不会触发联网下载**。
- ⚠️ **诚实边界**：这个结论是对**本机**成立。换一台没装 WebView2 的干净机器，安装时会联网从微软官方域名（`go.microsoft.com`）下载并静默安装 WebView2 —— 属 Windows 生态常规做法，但**它是"安装过程联网"**，需要知情。
- 下载地址是**微软官方 fwlink**，不是第三方域名；`Return='check'` ⇒ 失败会让安装报错（而非静默跳过）。

### 2.4 ⚠️ 未数字签名（要知情的第二件事）

实测（`Get-AuthenticodeSignature`）：

| 文件 | 状态 |
|---|---|
| `Vidigest_0.1.0_x64_en-US.msi` | **`NotSigned`** |
| `vidigest.exe` | **`NotSigned`** |

⇒ 安装时 UAC 会显示 **「未知发布者」**；若 MSI 来自网络下载（带 Mark-of-the-Web），SmartScreen 可能先拦一次。**这是"未签名"，不是"有问题"** —— 但正式分发前建议签名。

### 2.6 一个名不副实的 Feature（不是风险，但避免误读）

`main.wxs:2253-2260` 有个 Feature 名叫 **`PATH Environment Variable`** —— 看起来像要改 PATH，**实际不会**：

- 它的全部内容是 `<ComponentRef Id="Path"/>`，而 `Path` 就是**主程序组件**（`main.wxs:116-118`，即 `vidigest.exe`）。
- 该 Feature 同时被 `ShortcutsFeature`（`main.wxs:2244-2251`）引用。
- **整个 wxs 里没有任何 `<Environment>` 元素**（已 grep 确认 0 次）。

⇒ 这是 **Tauri 模板从 NSIS 时代沿用下来的命名**，功能上不回写 PATH。已用「无 `<Environment>` 元素」这条硬判据确认。

## 4. 卸载行为与残留

### 4.1 卸载会清掉什么（`msiexec /x {ProductCode}`，或「应用和功能」里卸载）

| 项 | 机制 |
|---|---|
| `C:\Program Files\Vidigest\` 整棵树（含 worker 与 2075 个运行时文件） | 每个文件都是组件的 KeyPath ⇒ 卸载删除；`RemoveFolder Id="INSTALLDIR" On="uninstall"` 收尾删空目录（`main.wxs:128-129`） |
| 桌面 `Vidigest.lnk` | 组件的 Shortcut 随组件卸载被删（`main.wxs:96`） |
| 开始菜单 `Vidigest\` 文件夹 + 快捷方式 | `RemoveFolder Id="ApplicationProgramsFolder" On="uninstall"`（`main.wxs:150`） |
| `HKCU\Software\benntqoo\Vidigest` 下的 4 个值 | 组件的 RegistryValue（KeyPath）随组件卸载被删 |

### 4.2 卸载**不会**删什么（这是设计，不是遗漏）

| 项 | 原因 |
|---|---|
| `%LOCALAPPDATA%\Vidigest\`（**你的笔记产物 / 数据库 / 配置**） | wxs 里 **`RemoveFile` 出现 0 次** ⇒ 本产品不删自身安装目录之外的任何文件。**卸载不丢数据**是期望行为 |
| `%LOCALAPPDATA%\com.benntqoo.vidigest\`（WebView 缓存） | MSI 不知道这个目录（由 Tauri 运行时创建） |
| 空的 `HKCU\Software\benntqoo` 键 | MSI 只删组件自己的值，**通常留下空键**（Windows 常见行为；未实测本包） |
| WebView2 运行时本身 | 若安装时被装上，则保留（其他程序可能共用，标准做法） |

### 4.3 若要「彻底清除」，手工补这一步（可选）

```powershell
# 1) 先正常卸载（设置 → 应用 → Vidigest）
# 2) 再删用户数据（确认不需要其中产物）
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\Vidigest"
Remove-Item -Recurse -Force "$env:LOCALAPPDATA\com.benntqoo.vidigest"
# 3) 清空键（若残留）
Remove-Item -Force "HKCU:\Software\benntqoo" -ErrorAction SilentlyContinue
```

⚠️ 第 2 步会**删掉你的转写产物与配置**，确认后再执行。

## 5. 「侵入系统 / 注入系统」核查

### 5.1 系统侵入面

§2.5 已列出全 0 项。另确认：

- **无开机自启**：`main.wxs` 无 `Run`/`RunOnce` 键；Rust 依赖里**无 `tauri-plugin-autostart`**。
- **无后台服务 / 计划任务**：全仓无 `schtasks` / `CreateService` / `OpenSCManager`。
- **无内容更新器**：**无 `tauri-plugin-updater`** ⇒ 不会自动联网检查更新。
- Tauri 权限（`app-ui/src-tauri/capabilities/default.json`）为**最小集**：只有 `core:default` + `opener:default` —— **未授予 shell / fs / http 等插件权限**。

### 5.2 注入类行为（代码审计）

| 面 | 结果 |
|---|---|
| Rust（`app-ui/src-tauri/src/**`） | **零命中**：无 `SetWindowsHook*` / `WriteProcessMemory` / `CreateRemoteThread` / `VirtualAllocEx` / `QueueUserAPC` / `LoadLibraryW(...)`（grep 全量） |
| Rust 依赖（`Cargo.toml`） | `tauri 2` / `tauri-plugin-opener` / `serde` / `serde_json` / `indexmap` + `windows-sys`（仅 features：`Foundation` / `System_JobObjects` / `Security` / `System_Threading`） ⇒ **只用 Job Object 做子进程管理** |
| Python（`app/**`） | 唯一注册表调用是 `app/core/env_probe.py:103-118` 的 **`winreg.QueryValueEx` 读 CPU 型号**（`HKEY_LOCAL_MACHINE` **只读**）；无写注册表、无 `schtasks`、无 `netsh`、无 Defender 相关调用 |
| 浏览器数据 | **不访问**。全仓 cookie 相关命中全部是**配置项与注释**（CLI 的 `--cookies` 参数、`CookieConfig`、`cookies_file`）；无 `Chrome`/`Edge`/`Login Data`/`Local State`/`playwright` 的读取代码（阶段 4 才计划做 cookie 自动获取） |
| 网络出口（运行时） | 仅三处，均为功能必需：**yt-dlp 下载视频**（平台域名）、**ffmpeg 本地处理**（不出网）、**汇总调 LLM API**（需自配 key）。安装阶段唯一可能的联网就是 §2.3 的 WebView2（本机不触发） |

### 5.3 ⚠️ 与「注入系统」的一处必须澄清的混淆

开发期在本项目里观察到过 `os error 231` 与 DLL 注入现象（`docs/阶段3_界面确认.md`）。**那与本产品无关**：

> 那是 **WorkBuddy 工具沙箱**注入的 `tsbx.dll` 拦截命名管道读方向，**只注入工具启动的进程**，且已用沙箱外对照实验闭合（沙箱外 29 模块、管道两向均正常）。

**Vidigest 自身不含任何注入行为**（§5.2）。
