# 多平台架构与批量下载（2026-10-26 设计）

> **状态**：平台注册表 + 作者列举后端已落地（判据 44~47）；**批量勾选 UI 未做**；
> 抖音的作者列举**未打通**（如实标注，见 §5）。
> 本文是"加平台时该动哪里"的唯一依据，改动前先读它。

## 1. 一句话

**平台之间的差异只有两处**：怎么拿会话、怎么列作者作品。下载本身交给 yt-dlp。
所以架构不是"每平台一个类"，而是"**一个通用实现 + 两个可覆写的能力**"。

## 2. 能力矩阵（现状）

| 平台 | 下载 | 列作者作品 | 需要会话 | 备注 |
|---|---|---|---|---|
| YouTube | yt-dlp | ✅ yt-dlp `--flat-playlist` | 可选 | 年龄限制 / 会员视频需 cookie |
| Bilibili | yt-dlp | ✅ 同上（空间投稿 / 合集） | 可选 | 不登录通常只能拿 480P |
| Twitter / X | yt-dlp | ⚠️ yt-dlp 支持用户时间线，未实测 | 多数需 cookie | `x.com` 与 `twitter.com` 同一站点 |
| 抖音 | yt-dlp（需 cookie） | ❌ **未打通** | **必需**（ttwid 匿名即可 24h） | 见 §5 |
| 本地文件 | 硬链接优先 | — | 无 | 没有"作者"概念 |
| 其他站点 | yt-dlp 通用兜底 | 视站点而定 | 视站点而定 | yt-dlp 覆盖 1800+ 站 |

**"未实测"必须写成未实测**：Twitter 的作者列举我还没跑过真实地址，
不能因为"yt-dlp 理论上支持"就算已验证（矩阵里用 ⚠️ 标出）。

## 3. 分层

```
app/core/urls.py          平台识别（正则，唯一真源）
      ↓
app/platforms/registry.py  resolve(url) → provider；能力位 supports_author
      ↓
app/platforms/base.py      协议：download() / list_author()、AuthorItem/AuthorPage、NotSupported
      ↓
app/platforms/ytdlp.py     通用实现（YouTube / Bilibili / Twitter / 其他）
app/platforms/douyin.py    只在**确有不同**时覆写（会话预检；作者列举如实 NotSupported）
app/platforms/local.py     本地文件
```

**为什么不把下载代码搬进 provider（本轮）**：`fetcher.download()` 是唯一有
7 条 `fetcher_selftest` + 完整 `rpc_smoke` 护着的热路径。搬家的收益是"结构漂亮"，
风险是"下载坏掉"。所以本轮 provider 的 `download()` **委托**回 `fetcher`，
等批量下载跑通、判据补齐后再搬（见 §6 第二阶段）。

## 4. 批量下载的数据流

```
用户填作者地址
   ↓  list_author {url, limit}
yt-dlp --flat-playlist -J  （或抖音专用实现）
   ↓  author_page {platform, title, total, truncated, items:[{url,title,duration,item_id,thumb}]}
UI 勾选
   ↓  add_tasks {urls:[...]}      ← **复用现有命令**，不新增
入队 → 现有流水线（下载 → 抽音频 → 转写 → 抽帧）
```

两个刻意的设计决定：

1. **列表条目直接带可下载 `url`**。这样"勾选 → 入队"不需要"从 id 反查地址"的
   第二套逻辑；拼不出地址的条目**直接丢弃**——列出来却下不了，比不列更糟。
2. **`truncated` 如实上报**。UI 要能说"还有更多"，而不是把 200 条当成全部。

## 5. 抖音：为什么作者列举是"未打通"

2026-10-26 三轮实测（详见 `.workbuddy/memory/2026-10-26.md`）：

| 试法 | 结果 |
|---|---|
| 纯 HTTP 无 cookie 打开短链 | 一律 302 到 `www.douyin.com` 首页，取不到 `aweme_id` |
| 老接口 `iesdouyin/web/api/v2/aweme/iteminfo` | 对**任何** id 都返回 200 + 0 字节（接口已下线） |
| 真实浏览器（playwright，匿名） | 能拿到 35 条 cookie（含 `ttwid`），但短链仍落到 `/jingxuan`，`<video>` 为空、0 条媒体请求 |

**还缺一块拼图**：一条"确定能在浏览器里正常播放"的抖音链接。
现有链接 `v.douyin.com/ye_7rRWF3tc` 要么已失效、要么匿名被拦 —— 两者当前
无法区分。拿一条有效链接跑 `tools/probe_douyin.py` 就能定性：

```bash
python tools/probe_douyin.py "https://v.douyin.com/xxxx/"          # 无头
python tools/probe_douyin.py "https://v.douyin.com/xxxx/" --warm   # 先暖会话
python tools/probe_douyin.py "https://v.douyin.com/xxxx/" --headed # 看得到浏览器
```

拦到 `.mp4` 直链 ⇒ 走"浏览器抓直链"；只拦到 blob/MSE ⇒ 需要拦 XHR 响应体；
什么都没有 ⇒ 这条路死，回到 cookie 方案。

## 7. 加一个新平台要动哪几处（清单）

1. `app/core/urls.py` 的 `URL_PATTERNS` 加一条（覆盖短链与站内长链两种形态）
2. `app/platforms/registry.py` 的 `_INSTANCES` 登记（默认用 `_generic(name)`）
3. **只有确有不同时**才新建 `app/platforms/<name>.py` 覆写 `list_author` / `require_session`
4. `tools/rpc_smoke.py` 的 `check_platform_registry` 加一条 URL 形态
5. 本节的能力矩阵加一行，**未实测的写 ⚠️**

漏了第 1 步 = 识别不到、落到 unknown（还可能"能用"，于是更隐蔽）；
漏了第 4 步 = 下次改正则时无人发现回归。
